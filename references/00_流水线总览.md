# 流程与验收

制作说明 → 核心句/歌词竞稿 → 六维文本评审 → top3×三种ACE方向 → 技术检查 → 匿名试听 → Suno成品与平台交付。

保留ACE候选路线；上述top3×三种方向适用于用户指定九条的批次，未指定规模时先做小样。试听后有三种去向：ACE成品已满意则直接交付；旋律/演唱方向满意则作为Suno音频母版继续制作；没有合适母版或需要拓展思路则使用Suno纯文本生成。Suno已有满意作品也可继续做母版，不必返回ACE重作。上传分类与分支选择见[17](17_音频上传与母版选择.md)。

| 阶段 | 产物 | 通过条件 |
|---|---|---|
| 制作说明 | 情绪落点、关系细节、声音辨识点 | 能说明为什么要唱、听众应留下什么感受 |
| 文本评审 | 六维分数、引用依据、独立规则诊断 | 当前稿件与要求匹配，所有配置评委完成；模型回避自评 |
| ACE | 9个wav、配置侧车、candidates.json；默认逐候选附Suno上传与More Options配置 | 指定3篇各3条，内容指纹匹配；逐条参数卡绑定对应音频；失败返回非零 |
| 分轨 | 完整人声供内部选段、末100秒清唱及时间元数据 | 采样率适配，片段来源与时间范围明确 |
| 技术验收 | 静音、时长、咬字差异、规格诊断 | 排除明显缺陷；不能凭BPM/五声度宣布最好听 |
| 试听 | 匿名音频、真实选择理由 | 同段落、相近时长、统一响度；没有真实选择时不生成胜负 |
| 交付 | Suno输入、上传类型与描述、More Options与本首参数卡、平台纯文本 | 标签用途正确，与当前定稿一致；音频来源SHA256匹配；界面请求值有来源，实际上传、模型与设置另行记录 |
| 共享交付（用户指定时） | 共享批次、逐文件SHA256校验记录、UNC入口 | 目标端文件与来源一致；Windows客户端可见性单独确认，未确认时如实标明 |

脚本用法见[编排说明](../scripts/README.md)。评分细节见[04](04_歌词曲调擂台.md)，试听步骤见[12](12_质量与试听.md)。

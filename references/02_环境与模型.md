# 02 · 环境与模型

本流水线的音频能力由本地 **audio.cpp 服务**提供（通过 HTTP 暴露），
Python 侧用 `WindowsAudioAPI` 客户端调用。服务地址由环境变量配置，**不写进仓库**。

> ⛔ 安全：服务地址、端口、任何密钥一律走环境变量（见文末「配置方式」）。

---

## 一、模型清单（GGUF，全部由 audio.cpp 服务加载）

| 能力 | 模型（GGUF） | 服务端 `model` 名 | 本流水线用途 | 必选？ |
|---|---|---|---|---|
| 出歌 | **ACE-Step 1.5** | `music` | 生成曲调/成曲（核心） | ✅ **必选** |
| 分轨 | **HTDemucs** | `sep` | 拆人声/鼓/贝斯/器乐 → 出清唱版 | ✅ **必选** |
| 转写 | **Qwen3-ASR 1.7B** | `asr` | 「输入是一首歌」时，转写歌词 | ⚪ 仅该输入形态需要 |
| 语音合成 | **Qwen3-TTS 12Hz 1.7B Base** | `tts` | 旁白/配音（MV 用，非出歌必需）| ⚪ 可选 |
| 音色克隆 | **CosyVoice3** | `clone` | 克隆音色（MV/口播用）| ⚪ 可选 |
| 歌词对轴 | **Qwen3-ForcedAligner 0.6B** | `align` | 歌词时间轴对齐（≤30s 片段，MV 字幕用）| ⚪ 可选 |

**核心出歌链路只依赖两个必选**：`music`（ACE-Step 出曲）＋ `sep`（HTDemucs 分轨出清唱）。
其余四个是「扩展能力」——只有特定输入形态或做 MV 时才用得到。

## 二、非模型依赖

| 依赖 | 用途 | 必选？ |
|---|---|---|
| **ffmpeg** | 转码/裁剪/淡出/静音检查 | ✅ **必选** |
| **Python 3.10+** | 跑编排脚本 | ✅ **必选** |
| `numpy` | 音频分析（分轨/静音/打分）| ✅ 必选 |
| `pypinyin` | 歌词押韵/可唱性评分 | ⚪ 擂台评分需要 |
| `librosa` | 节奏/调式分析 | ⚪ 候选打分需要 |
| `scipy`、`soundfile` | 显式重采样与音频读写 | ⚪ 候选诊断与回归检查需要 |
| `faster-whisper` | 本地转写兜底（服务不可用时的替代）| ⚪ 可选 |

> 说明：`WindowsAudioAPI` 客户端**只依赖 Python 标准库**（无第三方依赖）。
> 分析类工具（numpy/librosa/pypinyin）是评分/验收环节需要的，不是出歌硬依赖。

当前工作区已有分析环境，可用 `PY=<工作区>/tools/venv-sep/bin/python` 运行分析入口。回归检查：`<工作区>/tools/venv-sep/bin/python <工作区>/tools/test_song_quality.py`；普通系统Python可能缺少这些依赖。

## 四、配置方式（环境变量，不进仓库）

脚本统一从环境变量读敏感/环境相关的值，**仓库内不出现任何实际值**：

| 环境变量 | 含义 | 默认/说明 |
|---|---|---|
| `AUDIOCPP_HOST` | audio.cpp 服务地址 | 不写默认，必须配置 |
| `AUDIOCPP_PORT` | 服务端口 | 不写默认，必须配置 |
| 模型名 | 各能力 `model` 名 | 见上表，脚本内固定 |
| LLM 密钥等 | 擂台各模型 API key | 走本地 `.env`（已 gitignore） |

配置示例放在 `templates/env.example`（只含变量名与占位符，**不含真实值**）。

## 五、出歌时长安全闸（务必知道）

- 安全上界 **240s**；**500s 会卡死服务且无法取消，只能重启**。
- 歌词太短 → 模型「唱完补静音」→ 出完**必跑分段静音检查**。
- 脚本内置 `guard_duration`，超上限默认拒绝，需显式 `--allow-long` 才放行。

> 📌 **HTTP 端点 / 能力映射 / ACE 出歌参数（含实测）见 `references/10_音频接口.md`**。

## 六、可扩展性

新增音频能力时，按下面约定加，不破坏现有流程：

1. 在 audio.cpp 服务端加载新 GGUF 模型，登记一个 `model` 名。
2. 在 `WindowsAudioAPI`（或编排脚本）加一个薄方法，映射 `model` 名。
3. 在本表补一行：能力 / 模型 / 用途 / 必选与否。
4. 若是「出歌前必走」的新步骤，同时更新 `references/00_流水线总览.md` 的链路图。

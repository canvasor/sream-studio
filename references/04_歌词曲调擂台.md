# 文本竞稿与六维评审

同一制作说明交给多个模型。先看核心句是否自然、有辨识度，再展开完整歌词。文本评委不能判断尚未听到的旋律与演唱。

## 新版评分

六项为主题/人物关系、核心句记忆潜力、段落推进、清晰度、自然度、文本可唱性。每项1–10分并引用原词。文本初筛分=六项均值×10；字数、标题出现次数、押韵和结构的规则诊断不进入这个分数。

评委读取当前`ARENA_PROMPT`和命题列表，不沿用固定年代或固定曲风。回避自己的稿件；需完成所有配置中有资格的评委。缺评时标“待补评”，不填默认分。

记录写入`social/歌词提示词/scores_<TAG>/text-review-v2/`。缓存包含稿件、制作要求、评委提示词和版本指纹；改稿会创建新文件。旧四维文件不作为新版评分输入。

```bash
python scripts/arena.py gen --models m1,m2 --workers 2
python scripts/arena.py score --songs writer__0,other__1 --workers 2
python scripts/arena.py report
python scripts/arena.py top3
```

`judge`为`score`的兼容别名。`top3`实际导出3篇；底层导出器支持`--count`。只有评审完整、字段解析通过的稿件进入导出，之后仍需试听决定。

## 提示词

设置`ARENA_TAG`、`ARENA_PROMPT`与`ARENA_BRIEFS`；绝对路径也可用。新模板在`templates/prompts/`，当前工作区对应运行提示词也已同步。

不要为了标题复现、物件数量、句长交替或桥段换韵刷分。字数只提示可能的密度问题；是否唱顺要结合音频。参考曲解剖用于理解功能与手法，不逐项复刻数值和原文钩子。

# 产出与归档

当前工作区的试听、实验与新交付落在`processed_songs/<批次>/`。建议批次包含：原始制作说明、各稿件、版本化评审、ACE候选清单及侧车、完整人声/末100秒片段、Suno交付、匿名试听与偏好记录。

历史评分、已选稿件与原音频保留，新版本另存。试听公开目录只含匿名音频、播放器和待填写记录；来源映射留在旁边的`*_private_key.json`，完成选择后再查看。

## 共享盘与Windows试听交付

用户指定共享目录，或要求从Windows共享区试听时，同步是交付的一部分，试听批次不必等作品定稿。已有授权直接续做，不重复询问是否开始；未指定共享交付时保留工作区产物。文件系统权限不足时使用正常的权限申请，不绕过限制。发布作品与定稿归档另按用户要求执行。

先完成当前批次的音频、清唱、歌词与试听验收，再使用[同步脚本](../scripts/sync_delivery.py)。源目录只选本批交付，不能把包含凭据的整个工作区当作来源。共享目录与UNC地址通过当次参数提供，不写入技能仓库。

```bash
python scripts/sync_delivery.py --source /path/to/processed_songs/batch-v1 \
  --dest-parent /path/to/shared/processed_songs --dry-run
python scripts/sync_delivery.py --source /path/to/processed_songs/batch-v1 \
  --dest-parent /path/to/shared/processed_songs
```

脚本先复制到共享父目录下的暂存目录，逐文件比较SHA256，再发布为同名批次目录，保留工作区原件。它排除缓存与旧同步记录，拒绝符号链接，生成`共享同步校验.json`。复制校验只证明文件一致，不能替代音频质量验收。

已有目标只核对，不覆盖或删除；稿件或目标内容不一致时停止，另建版本。源文件未变时，失败后加`--resume`续跑相同命令；暂存来源不匹配、源文件变化或权限失败时停止并报告，不循环重试。只读复核使用`--check-only`，也可核对本次迁移前的同结构SHA256记录。

## Windows可见性与交付回复

确认实际Samba导出目录或挂载映射；本机同名路径存在不能证明UNC映射正确。目标在工作区之外时，应从有权限的共享服务所在环境复核。可选`--unc-root`传入共享父目录的UNC路径，脚本打印其下的批次入口；这只生成路径，不证明Windows已访问成功。

HTML播放器与播放列表使用相对音频路径，便于共享目录内直接播放。若Windows列表未出现新批次，先在客户端直接检查完整路径：

```powershell
$batch = Read-Host '粘贴完整的UNC批次目录'
Test-Path -LiteralPath $batch
Get-ChildItem -LiteralPath $batch
```

核对同步时间、直接访问结果、共享映射和权限后再判断缓存；没有证据时不把缺失归因于缓存，不默认要求重启或修改SMB配置。无法直接运行客户端检查时，请用户确认，并在运行记录标明“Windows可见性待确认”；用户确认后更新该状态，保留原校验记录作为同步时的证据。

最终回复分别说明实际生成数量、共享端复制与校验结果、Windows可见性状态，给出完整UNC批次路径及`分曲盲听/<歌名>/试听.html`或统一试听入口。若共享同步尚未完成，明确已完成的工作区产物和具体阻碍。

## 归档

用户定稿后按已有作品库约定归档。

音视频、真实评分及本地记录不提交技能仓库；技能仓库保留流程、模板、脚本与无敏感信息的样例。

## 已归档临时批次的清理

`processed_songs/`是生成中的临时区。作品定稿进入作品库并核对文件后，按用户明确指定的作品与范围清理临时目录；不把已删除批次重新生成或同步回来。
清理前区分正式作品、临时媒体与可复用代码、技能、字体和模型；保留需要的工具。具体已归档批次、清理清单与执行记录留在本地文档，不写入通用技能参考。

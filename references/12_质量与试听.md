# 质量判断与试听反馈

## 先确定要改善什么

涉及原唱与翻唱对比、主副歌反差或“穿透力”时，先按[14_参考对比与副歌设计](14_参考对比与副歌设计.md)定位实际片段、拆解声音目标并核对实际生成请求。

| 感受 | 先检查 | 一次可尝试的变化 |
|---|---|---|
| 副歌记不住 | 核心句与实际旋律动机、第一次出现的位置 | 保留歌词比较三种音乐方向，或只改核心句的一种表达 |
| 词很工整但不像人说话 | 为字数/押韵改动过的句子、泛化的副歌 | 保留人物关系细节，只改一至两处回应句 |
| 情绪没打动人 | 人物为何要唱、主副歌反差、演唱距离 | 同词比较近距离叙述与更开放的副歌 |
| 每首相似 | 常驻模板、固定BPM、固定物件和结局 | 只保留本次最重要的1–2个表达任务 |

## 三层验收

1. 技术：静音、截断、解析缺失、ASR与歌词差异。ASR误识别需核实，不能直接等同于唱错。
2. 规格诊断：速度、脉冲、音高分布、动态。它们说明匹配程度，不证明更动人。
3. 艺术选择：真实的匿名试听。比较核心句、想再听的程度、演唱可信度和段落推进。

## 生成匿名试听

先按每条音频的真实段落确定起止点。长度一致通常选20–35秒或完整两遍hook；时间点可以因版本而异。

保存一份JSON，`file`可用相对于JSON的路径：

```json
{
  "clips": [
    {"file": "take1.wav", "start": 40, "end": 64},
    {"file": "take2.wav", "start": 42, "end": 66}
  ]
}
```

```bash
python scripts/listening_test.py prepare --manifest clips.json --out listening-v1
```

工具用FFmpeg两遍响度归一，生成匿名A/B音频、`试听.html`与空的`ratings.json`。来源映射和实测响度留在同级`listening-v1_private_key.json`；先听再看。

先独立听一遍，隔一段时间记录记住的一句，再比较哪条更愿意重听。允许平局，理由指向具体一句或唱法。

```bash
python scripts/listening_test.py record --ratings listening-v1/ratings.json \
  --pair A,B --choice B --reason '第二句的停顿更自然' --remembered '听后记住的那句'
python scripts/listening_test.py summarize --ratings listening-v1/ratings.json \
  --key listening-v1_private_key.json --out preference-v1.json
```

没有真实选择时汇总命令会失败。选择记录用于这首歌和个人偏好的判断；样本不足或对比次数不等，不能推广成模型排名。

## 返工

只改导致落选的一个主要变量，保留原版，再试听一次。ACE参考是否有用与Suno成品是否好听分别评价。文本新稿没有音频时只称待验证的改写，不称升级成功。

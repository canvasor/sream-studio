# 16 · 驾车行车 MV（歌 + 第一视角行车画面）

用一首歌 + 第一视角行车片段，快速出一条「一直在路上」的竖屏歌词 MV。
产出：成片（高清 + 上传版）+ 发布文案。

## 适用

- 用户给一首歌（mp3/wav），要一条**行车/公路**风格的歌词视频
- 参考模式：**0–3s 封面 → 3s 后只剩行车画面 + 底部逐句歌词**

## 成品规格（默认）

| 项 | 值 |
|---|---|
| 画幅 | **9:16**（1440×2560 或 1080×1920） |
| 帧率 | 30fps |
| 时长 | = 歌曲时长（不循环、不裁歌） |
| 封面 | 前 **3 秒**，叠在画面上（歌名 / 演唱 / 版本标签） |
| 字幕 | 底部单行，白字黑边，逐句 |
| 音轨 | 直接用歌曲，不加 BGM、不 TTS |

## 步骤

### ① 找行车素材（Pexels）

```
搜索词：driving highway pov / car driving road / highway driving
筛选：orientation=portrait（9:16），duration ≥ 30s，宽 ≥1080
```

⭐ **累计时长要 ≥ 歌曲时长**：优先用「几段长片拼起来」，**不用循环**。
循环在同一段素材里反复播放，接缝处画面会"跳"，长视频里很明显。

> ⛔ **坑 1：Pexels 必须带浏览器 User-Agent**
> 默认 `Python-urllib/3.x` 会被 Cloudflare 拦成 **403 / error code 1010**。
> 必须带 `User-Agent: Mozilla/5.0 ... Chrome/xxx`。

> ⛔ **坑 2：不要用带水印的现成视频**
> 抖音下载的素材都带「抖音号」水印，二次发布会被限流。
> 只用 Pexels 这类可商用素材，或用户自己拍的。

### ② 规划拼接（不输出中间视频）

素材的缩放、裁切、时间戳归零、慢放和`xfade`统一放进最终滤镜图，不先生成`base.mp4`。段间默认0.5秒溶解；极短素材会缩短转场，防止超过片段长度。

扣除转场重叠后素材不足时，整体慢放补齐，不循环画面。伸长系数按`max(1, (歌曲时长 + 转场重叠总长) / 素材原总长)`计算，再据慢放后的各段时长定位转场，避免补时计算遗漏溶解重叠。每个输入先归零时间戳并统一到30fps与同一时间基。

### ③ 歌词时间轴（whisper）

```python
from faster_whisper import WhisperModel
import soundfile as sf
a, sr = sf.read(wav16k, dtype="float32")     # ⭐ 喂数组，不喂文件
m = WhisperModel("模型目录", device="cpu", compute_type="int8")
segs, _ = m.transcribe(a, language="zh", word_timestamps=False, vad_filter=False, beam_size=5)
```

> ⛔ **坑 3：faster-whisper 别直接喂文件路径**
> 某些 PyAV 版本会报 `TypeError: open() got an unexpected keyword argument 'metadata_errors'`。
> **用 soundfile 读成 numpy 数组再喂**，绕开 PyAV 解码。

> ⛔ **坑 4：whisper 的**文字**不可信，别直接用**
> 唱腔识别错误率高，实测会把「遇上你是我的**缘**」听成「眼」、「雪莲花」听成「雪的地方」，
> 还会输出**繁体**。
> **正确做法**：whisper 只取**时间轴**，文字用**已知歌词**逐句替换。

正式出片必须提供`--lyrics`，采用平台纯文本歌词，一行一句、重复句完整展开。先检查行数、时间范围、重叠和句子对应关系，再制作画面。脚本将ASR结果保存为`_work/歌词时间轴_待核对.json`；不匹配即返回失败，不回退到ASR唱词，也不继续下载素材或合成视频。

文字对应检查忽略标点与空白，使用0.75相似度下限拦截明显错位，允许少量近音误识别；它是检查手段，不是强制对齐算法或逐句时间正确的证明。字幕最终一律使用提供的正确歌词，仍须试听核对。

若Whisper把一句拆成多段、漏句或时间错位，保留原歌词，人工或使用已配置的对齐工具修正时间轴。修正文件可为数组，或含`rows`数组的对象：

```json
[
  {"start": 12.5, "end": 16.8, "text": "第一句正确歌词"},
  {"start": 17.2, "end": 21.0, "text": "第二句正确歌词"}
]
```

`text`与歌词逐句对应，`start/end`为歌曲起点起算的秒数，时间单调、不重叠且不超出歌曲。传`--timings /path/to/corrected.json`恢复制作，会跳过Whisper，无需再次识别或下载模型。不要为了凑段数删除唱词或重复句。

### ④ 封面（0–3s）

用 PIL 画一张透明 PNG（比 `drawtext` 好控制竖排/描边），再 overlay：

```
歌名   居中，约 15% 高度，字号 ~112（1440 宽）
演唱   居中，约 22.5%，字号 ~74
版本   （如「完整版」）右侧竖排，约 30% 起
样式   白字 + 黑描边（stroke ~9px），粗圆字体（汉仪超粗圆简）
```

叠加：`overlay=0:0:enable='between(t,0,3)'`

> ⛔ **封面标签要和版本一致**
> 只有**整首**才写「完整版」；**30 秒片段**绝不能写「完整版」（那是骗人，也会让用户预期落空）。
> 片段版封面只留「歌名 + 演唱」，或写「精选片段」。

### ⑤ 一次成型（关键）

**拼接、字幕、封面、音轨在一次FFmpeg调用中直接输出两个版本**：

```text
原素材 → 缩放/裁切/慢放/溶解 → 封面+字幕 → split → 高清版编码
                                              └→ 上传版编码
原歌曲音轨 ─────────────────────────────────────→ 两路音频编码
```

两个版本都直接来自同一合成结果，各自只经过一次最终视频编码；不生成`base_merged.mp4`，上传版也不再从高清成片转码。两路输出都以歌曲时长为限，画面不循环。滤镜图在`_work`中引用固定名称`lyrics.ass`，素材和输出使用绝对路径，支持目录含空格或单引号。

素材编排可借鉴MPT，编码实现以脚本为准，不能仅凭工具名称推定编码次数。`python3 scripts/test_drive_mv.py`含本地短素材渲染测试，核查双版本时长、转场、封面消失与有声音轨；不调用在线模型或下载素材。

### ⑥ 交付

| 产物 | 说明 |
|---|---|
| `*_高清.mp4` | crf20，存档；码率和体积随内容变化 |
| `*_上传版.mp4` | crf24 + maxrate 8M；体积随时长和内容变化 |
| `发布文案.md` | 标题/正文/话题标签/发布设置 |

放共享盘 `processed_songs/<歌名>_驾车MV_<日期>/`（见 `11_产出与归档.md`）。

**发布文案的话题标签固定口径（5 个）**：

```
#AI新声计划 #音乐种草计划 #<歌名> <两个可配>
```

- 前两个**每首必带**；第三个是歌名标签
- 后两个按内容选，默认 `#翻唱 #车载音乐`；可用 `--tags "翻唱 开车必听"` 覆盖
- 不要堆满 10 个以上，平台会判「堆标签」

## 验收清单

- [ ] 0–3s 有封面，3.5s 后**完全消失**
- [ ] 字幕文字正确（**不是** whisper 原文）、时间轴对齐
- [ ] 歌词或时间轴不匹配时停止；修正后用`--timings`恢复，不静默回退
- [ ] 音轨有声（`volumedetect` 不是 -inf）
- [ ] 段间是溶解不是硬切
- [ ] 时长 = 歌曲时长（±0.5s）
- [ ] 上传版能正常播放
- [ ] 两个版本直接从原素材合成，各只编码一次，无中间合成视频

## 命令

```bash
python scripts/drive_mv.py --song <歌曲> --title <歌名> --singer <演唱者> \
    --lyrics <歌词.txt> --out <输出目录>

# 已校对时间轴时跳过Whisper
python scripts/drive_mv.py --song <歌曲> --title <歌名> --singer <演唱者> \
    --lyrics <歌词.txt> --timings <校对时间轴.json> --clips <A.mp4,B.mp4> --out <新输出目录>
```

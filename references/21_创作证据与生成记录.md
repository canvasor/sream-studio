# 创作证据与生成记录

三个脚本整理本地材料，不提交存证服务、版权登记或音乐平台。实际记录与产物留在仓库外。

| 脚本 | 作用 | 已有产物 |
|---|---|---|
| `scripts/make_evidence_pack.py` | 收集现有归档文件、音频指纹、文件时间及ZIP | 同名目录或ZIP存在即拒绝；换新的`--out`父目录 |
| `scripts/make_generation_record.py` | 将当前配置、歌词与截图清单整理成待核实草稿 | 默认跳过；`--force`先保留独立备份再替换 |
| `scripts/recover_generation_record.py` | 用同名PDF与完整Styles/Lyrics原文恢复记录 | 默认跳过；缺少完整原文或预期PDF结构时停止；`--force`先备份 |

三者都支持`--dry-run`，只读检查，不写档案、备份或ZIP。`--help`无需本地目录或第三方依赖；恢复脚本实际提取PDF时另需`pdftotext`。

## 本地配置

| 环境变量 | 默认 | 说明 |
|---|---|---|
| `WORKSPACE_DIR` | `~/dsh-workspace` | 证据输出的默认工作区 |
| `TOOLS_DIR` | `~/dsh-workspace/tools` | 本地`release_meta.py`所在目录，与其他编排脚本一致 |
| `MUSIC_LIBRARY_DIR` | `~/music-studio/作品库` | 作品根目录 |
| `EVIDENCE_OUT` | `<WORKSPACE_DIR>/账号资料/创作证据包` | 也可用证据脚本的`--out`覆盖；须位于作品库之外 |

`release_meta.py`是本地歌曲目录，不随技能分发。示例字段均为虚构值：

```python
SONGS = [{
    "name": "示例歌曲",
    "lib_dir": "01_示例歌曲",
    "wav": "示例歌曲.wav",
    "dur": "03:00",
    "album": "示例专辑",
    "ly_src": "本地稿件，待核实来源",
}]
```

`name`、`lib_dir`、`wav`必须是单个文件或目录名。常用作品子目录为`01_音频母版/`、`03_封面/`、`04_歌词/`、`05_生成记录/`和`06_文档/`。
`--song`按名称包含匹配；`--album`按目录中的专辑字段匹配，兼容历史高原三帖目录。执行前用预览核对选择范围。

```bash
python3 scripts/make_evidence_pack.py --song 示例歌曲 --out /path/to/evidence-v1 --dry-run
python3 scripts/make_generation_record.py --album 示例专辑 --dry-run
python3 scripts/recover_generation_record.py --song 示例歌曲 --dry-run
```

核对后移除`--dry-run`执行。恢复脚本读取`05_生成记录/<歌名>.pdf`和`04_歌词/歌词_Suno原文.md`中的`### Styles`、`### Lyrics`代码块，结果需人工与原文件比对。

## 证据范围

证据包保留子目录层级，避免同名配置或截图覆盖；复制后验证SHA256。`02_manifest.json`记录原作品相对路径，已复制文件另有`pack_path`；音频本体不入包，仅记录指纹。`01_清单_SHA256.txt`中的路径相对包目录，可校验包中实际文件（清单自身除外）。中断或校验失败时不产出完成ZIP，残留目录需人工检查，重做时选择新输出目录。

SHA256证明文件一致，文件修改时间只辅助梳理顺序，均不单独证明创作时间或权利归属。当前配置也不自动等于生成时输入。记录草稿不能自动填入订阅日期、商用许可结论、发布状态或人工创作经历；这些事实应由原始记录支持。缺失文件不会自动补齐，对外提交前按实际接收方要求审阅材料。

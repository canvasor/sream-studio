## 二、每个模型 4 个必填参数（编号 n，从 1 开始）

| 参数 | 说明 | 例子 |
|---|---|---|
| `LLMn_NAME` | **模型名称**（调用时传的 model id） | `deepseek-chat` |
| `LLMn_BASE` | **base url**（填根路径或带 `/v1` 都行，脚本自动补） | `https://api.deepseek.com` |
| `LLMn_PROTO` | **对话协议**：`OpenAI` 或 `Anthropic` | `OpenAI` |
| `LLMn_KEY` | **api key** | `sk-…` |

**2 个可选**：`LLMn_TIMEOUT`（秒，默认 600）、`LLMn_MAXTOK`（默认 8000）

**要点**
- **编号可以跳号** —— 脚本扫 1~99，凡是填了 `NAME` 的就生效
- **不同服务商就写不同编号**（每个模型各自带自己的 base url，天然支持多个 base url）
- `=` 后面**不要加引号和空格**，模型名/base 用英文原样填

### 常用 base url 参考

| 服务商 | base url | 协议 |
|---|---|---|
| DeepSeek | `https://api.deepseek.com` | OpenAI |
| 阿里百炼（兼容模式） | `https://dashscope.aliyuncs.com/compatible-mode/v1` | OpenAI |
| 月之暗面 Kimi | `https://api.moonshot.cn` | OpenAI |

| OpenAI | `https://api.openai.com/v1` | OpenAI |
| Anthropic Claude | `https://api.anthropic.com` | **Anthropic** |

## 四、填好之后怎么用

**什么都不用改** —— 擂台启动时会**自动**把配置里的模型并进模型表：

```bash
# 第一段：歌词擂台（多了你配的模型）
ARENA_TAG=dj ARENA_PROMPT=prompt_DJ.md ARENA_BRIEFS=briefs_DJ.json \
  python3 tools/lyrics_arena.py gen

# 第二段：音色配置擂台（同样自动带上）
python3 tools/timbre_config_arena.py --lyrics <Top目录> --brief <简报> --out <文档>
```

⚠️ **这些自定义模型走 `custom` 通道，和阿里/方舟各自独立并发**：
阿里仍是串行（`BAILIAN_CONCURRENCY=1`），方舟 3 并发，
**自定义模型每个一次调用、互不干扰**（`--workers` 控制总并发）。

## 五、底层实现（出问题时可查）

`tools/llm_client.py`
- **一律用流式（SSE）** —— 非流式要等整篇生成完才返回响应头，长文必撞超时（我们在 `bl` 上踩过）
- 端点自动拼装 + **404 自动试下一个候选**（对付"有的服务商不要 `/v1`"）
- 两种协议的字段位置都兼容：
  - OpenAI：`choices[0].delta.content`
  - Anthropic：`content_block_delta` → `delta.text`
- 回归测试：`python3 tools/test_llm_client.py`（本地假 SSE 服务器，不联网、不用密钥）

## 六、⭐ 并发限流：**同一个 api key 最多 3 个并发**

**规则**：按 **api key**（不是按 base url、也不是按模型名）分组，**每组最多 3 个并发**。
可用环境变量 `LLM_KEY_CONCURRENCY` 改（默认 3）。

**你这套配置的实际效果**：

| key 组 | 模型 | 并发上限 |
|---|---|---|
| `86c98db3` | gpt-6-sol | **1**（独占一个 key，自己一路） |
| `47749dce` | grok-4.7 / hy4-preview / mimo-v2.6-pro / claude-haiku-5-5 / minimax-m3 | **3** |

> 两组**各自独立** —— 所以"5 个共用 key 的那组跑 3 个"和"gpt-6-sol 跑 1 个"可以**同时进行**，合计 4 个在飞。
>
> ⚠️ **不是按 base url 限流** —— 同一个 base url 挂多个模型是正常用法，不该被合并限流。

查看分组：`python3 tools/llm_client.py list`
回归测试：`python3 tools/test_llm_ratelimit.py`（本地假服务器，实测最大并发数）

## 七、⭐ 关掉「思考」提速（思考型模型必看）

**问题**：思考型模型（如 `hy4-preview`、`mimo-v2.6-pro`）默认把大量 token 花在**内心独白**上 ——
一篇歌词要 **500~800 秒**；预算给小了还会把独白当正文吐出来。

**解法**：用 `LLMn_EXTRA` 传「关闭思考」的参数（JSON，合并到请求体顶层）。

### ⚠️ 不是所有写法都能关

| 模型 | 有效写法 | 无效/更糟的写法 |
|---|---|---|
| `hy4-preview` | `{"reasoning_effort":"none"}` | ❌ `"low"` —— 不是关、只是减预算，**更慢且正文为空**（实测 30.8s / 正文 0 字） |
| `mimo-v2.6-pro` | `{"thinking":{"type":"disabled"}}` | —（`{"reasoning_effort":"none"}` 也有效） |

### 配置写法

```bash
LLM1_NAME=hy4-preview
LLM1_BASE=https://你的网关/v1
LLM1_PROTO=OpenAI
LLM1_KEY=sk-…
LLM1_MAXTOK=32000
LLM1_EXTRA={"reasoning_effort":"none"}       # ⭐ 关思考

LLM2_NAME=mimo-v2.6-pro
LLM2_BASE=https://你的网关/v1
LLM2_PROTO=OpenAI
LLM2_KEY=sk-…
LLM2_MAXTOK=32000
LLM2_EXTRA={"thinking":{"type":"disabled"}}  # ⭐ 关思考
```

### 实测效果（2026-10-09，用完整 DJ 提示词生成一整首歌词）

| 模型 | 关思考前 | 关思考后 | 倍数 |
|---|---|---|---|
| `hy4-preview` | 500~800s | **25.1s** | **~25×** |
| `mimo-v2.6-pro` | ~200~400s | **26.6s** | **~10×** |

**质量未降**：输出 1860 字、歌词中文占比 44%、结构标签完整。

### 怎么判断「真的关掉了」

**不要只看耗时，也不要只看客户端有没有显示思考内容** ——
要读**原始 SSE 流**里还有没有 `delta.reasoning` / `delta.reasoning_content`。
用 `tools/check_thinking.py <模型名>` 一条命令验证（脚本已随工具提供）。

> ⚠️ 中转链路（sub2api / OpenCode Go 等）**可能过滤掉这些参数**。
> **必须实测，不能假设。**

### 通用规则

`LLMn_EXTRA` 是 **JSON 对象**，会**合并到请求体顶层**，可放任何该服务商支持的字段：
- `{"reasoning_effort":"none"}` —— 关思考（部分模型）
- `{"thinking":{"type":"disabled"}}` —— 关思考（MiMo 官方写法）
- `{"temperature":0.7}`、`{"top_p":0.9}` —— 采样参数
- `{"chat_template_kwargs":{"enable_thinking":false}}` —— 另一种常见的关思考写法

⚠️ 它**放在最后合并**，所以能覆盖默认字段（包括 `max_tokens`）。

## 八、🖼 图片模型（OpenAI 图片接口）

图片模型**挂在某个 `LLMn` 块下**，默认复用它的 `BASE` / `PROTO` / `KEY`（可各自覆盖）。

### 配置写法

```bash
LLM1_NAME=gpt-6-sol                    # 父块（提供 base/key）
LLM1_BASE=https://你的网关/v1
LLM1_PROTO=OpenAI
LLM1_KEY=sk-…

LLM1_IMAGE_FLARE_NAME=gpt-image-2.5-flare        # ← 定义图片模型 1
LLM1_IMAGE_SUNBURST_NAME=gpt-image-2.5-sunburst  # ← 定义图片模型 2
```

每个图片模型可选的覆盖项：

| 字段 | 说明 | 默认 |
|---|---|---|
| `LLMn_IMAGE_<TAG>_NAME` | **模型名（必填，填了才生效）** | — |
| `LLMn_IMAGE_<TAG>_BASE` | 单独的 base url | 父块的 |
| `LLMn_IMAGE_<TAG>_KEY` | 单独的 key | 父块的 |
| `LLMn_IMAGE_<TAG>_PROTO` | 单独的协议 | 父块的 |
| `LLMn_IMAGE_<TAG>_SIZE` | **画幅比例**，如 `9:16`（写进提示词，唯一有效的画幅控制方式） | `9:16` |
| `LLMn_IMAGE_<TAG>_OUTSIZE` | **最终出图尺寸**，生成后自动 cover 缩放裁切 | `1440x2560` |
| `LLMn_IMAGE_<TAG>_EXTRA` | JSON，合并到请求体顶层 | — |

`<TAG>` 随便起（如 `FLARE`），只是同一块下多个图片模型的区分标签。

### 用法

```bash
python3 tools/llm_client.py images                    # 列出图片模型
python3 tools/llm_client.py image \
  --model gpt-image-2.5-flare \
  --prompt "清晨的高架桥，雾，电影感" \
  --size 9:16 \
  --out out.jpg
```

### 🔴 画幅只能靠**提示词**控制（重要）

实测（2026-10-09，用户的 sub2api 网关）：**`size` / `aspect_ratio` / `width,height` 参数全部被忽略**，
无论传什么，输出画幅都是随机的。

**唯一可靠的办法是把画幅写进提示词** —— 实测非常稳定、可复现：

| 提示词里写 | 实际输出 | 比例 |
|---|---|---|
| `9:16 vertical portrait composition` | **941×1672** | 0.563（精确 9:16）✅ |
| `16:9 horizontal landscape composition` | **1672×941** | 1.777 ✅ |
| `1:1 square composition` | **1254×1254** | 1.000 ✅ |
| 不写（对照） | 1370×1148 / 1024×1536 … | **随机** ❌ |

所以工具里做了自动处理：`--size 9:16` 会**自动把画幅描述拼进提示词**（提示词里已经写过比例的不会重复加）。

> ✅ **2K 已自动处理**（不用你手动放大）：
> 实测模型**最高只能出 941×1672**，`2K` / `1440x2560` / `quality:high|hd` / `resolution:2K`
> **全部无效** —— 所以工具在生成后**自动 cover 缩放裁切**到 `OUTSIZE`（默认 `1440×2560`），
> 用的是和封面流水线 `tools/make_hook_cover.py` 同一套 PIL LANCZOS 做法。
> 从 941×1672 到 1440×2560 只放大 **1.53 倍**，质量可接受（实测出图 886 KB / 797 KB，清晰无糊）。


### 调用形态（实测都通）

| 形态 | 结果 |
|---|---|
| `POST {base}/images/generations` 最小体 | ✅ 24.1s |
| + `response_format=b64_json` | ✅ 23.9s（默认就回 b64，加不加都行） |
| + `quality` | ✅ 21.0s |

返回 `data[0].b64_json`；若服务商返回 `data[0].url`，工具也会自动下载。

### 参数已固定（2026-10-09）

```bash
LLM1_IMAGE_FLARE_NAME=gpt-image-2.5-flare
LLM1_IMAGE_FLARE_SIZE=9:16          # 画幅（写进提示词）
LLM1_IMAGE_FLARE_OUTSIZE=1440x2560  # 最终尺寸（生成后自动 cover 裁切）

LLM1_IMAGE_SUNBURST_NAME=gpt-image-2.5-sunburst
LLM1_IMAGE_SUNBURST_SIZE=9:16
LLM1_IMAGE_SUNBURST_OUTSIZE=1440x2560
```

**和豆包那套对齐**：输出 **1440×2560 竖版 2K**，与 `tools/make_hook_cover.py` 的 `SIZE` 一致。

直接出图（不用再加任何参数）：

```bash
python3 tools/llm_client.py image \
  --model gpt-image-2.5-flare \
  --prompt "清晨的高架桥，薄雾，一辆车的尾灯，电影感，冷色调" \
  --out out.jpg
# → ✅ out.jpg  (1440, 2560)  ~886 KB
```

要临时换尺寸：`--size 16:9 --out-size 2560x1440`
